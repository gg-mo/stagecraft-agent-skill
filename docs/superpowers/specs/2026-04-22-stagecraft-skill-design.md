# Stagecraft Skill — Design Spec

**Date:** 2026-04-22
**Status:** Approved for implementation planning
**Repo:** `stagecraft-agent-skill`

---

## 1. Motivation

The author has a long-form prompt they invoke by hand to get coding agents to produce premium, keynote-style UI with restrained motion. The prompt works, but copy-pasting it every session is friction, and the output still varies across agents and harnesses because the prompt is descriptive, not prescriptive.

Goal: package the prompt's intent as a portable, deterministic skill that any coding agent (Claude Code, Copilot CLI, Cursor, Codex, Gemini CLI) can consume and apply consistently.

A prior draft (generated by ChatGPT) captured the vocabulary but failed as a skill artifact. Its weaknesses shape this design:

- No frontmatter, so no invocation trigger.
- Monolithic prose (~400 lines), no progressive disclosure.
- Descriptive, not prescriptive — still required the agent to invent timings, easings, component patterns.
- No reusable primitives, no before/after anchors.
- Principles restated in three sections each.
- No differentiation from the existing generic `frontend-design` skill.

This spec corrects all of the above.

## 2. Goals

1. **Determinism.** Two different agents on two different harnesses, given the same task, produce visually consistent output — same timings, same easing, same type scale.
2. **Portability.** One source of truth, consumable from five environments without per-environment drift.
3. **Composability.** The skill layers onto whatever frontend workflow the agent already uses. It does not fight or replace general UI skills.
4. **Clear differentiation.** The skill triggers on intent ("keynote," "premium," "cinematic," "launch page") — not on any UI task — and has a specific Mode C "audit and elevate" workflow that generic frontend skills lack.
5. **Restraint-first defaults.** Every primitive shipped is tuned toward quiet polish, not showy effects. Anti-patterns are called out explicitly so agents can self-check.

## 3. Non-goals

- Shipping a runtime npm package. Introducing a dependency into every target project loses portability and adds long-term maintenance.
- Covering every frontend stack. Primary stack is React + Tailwind + Framer Motion; CSS-animation fallbacks ship alongside for projects without Framer. Vue/Svelte users adapt the CSS fallbacks.
- Replacing general frontend skills. Stagecraft is a style/motion specialization.
- Design-tool integration (Figma, etc.). Out of scope.

## 4. Architecture: Approach B — Skill + Code Primitives + Audit Kit

**Consumer modes the skill supports:**

- **Mode A — Style layer.** Applied mid-flight while the agent builds UI via its normal workflow. Transforms palette, spacing, type, and motion to keynote-style.
- **Mode C — Audit and elevate.** Given an existing screen (code or description), score it against Stagecraft dimensions, rank changes by impact, apply them.

Mode B (own the whole page from scratch) is deliberately not a distinct mode; it is covered by Mode A applied during new-component work.

### 4.2 Design principles

- **Progressive disclosure.** SKILL.md is short and only points at references. References are loaded by the agent on demand.
- **Single source of truth.** `SKILL.md` + `references/` are canonical. Integration wrappers are generated, never hand-edited.
- **Copy-pasteable primitives.** Every motion token ships with exact values and working code. Agents do not guess durations or easings.

## 5. `SKILL.md` — entry point

Target length: ~80 lines.

Required frontmatter:

```yaml
---
name: stagecraft
description: Use when the user wants premium, keynote-style UI with
  refined motion — dark, minimal, cinematic reveals. Trigger words:
  "premium," "polished," "cinematic," "Apple-like," "keynote,"
  "launch page," "product reveal." Also use when asked to audit or
  elevate an existing screen to feel more restrained and intentional.
---
```

Body sections:

1. **Mission** (one paragraph) — the "premium through restraint" frame.
2. **When to use** — bulleted trigger contexts.
3. **When not to use** — playful, gamified, maximalist, dense enterprise tables.
4. **Workflow** (5 numbered steps, each one line pointing at a reference):
   1. Identify UI intent + what must remain usable.
   2. Apply visual system → `references/visual-system.md`.
   3. Apply motion tokens → `references/motion-tokens.md`.
   4. Apply reveal sequencing → `references/reveal-patterns.md`.
   5. Run audit → `references/audit-checklist.md`.
5. **The restraint bar** (3–4 sentences) — the "if it feels eager to impress, it's too much; if it feels inevitable, it's correct" ethos.

No principles repeated in references. Each file owns its scope.

## 6. `references/motion-tokens.md`

### 6.1 Token table

| Token | Duration | Easing | Transform | Use |
|---|---|---|---|---|
| `sceneEnter` | 0.8s | `[0.22, 1, 0.36, 1]` | opacity 0→1 | page/scene open |
| `fadeUp` | 0.6s | `[0.22, 1, 0.36, 1]` | y 16px→0, op 0→1 | default entrance |
| `fadeIn` | 0.5s | `[0.4, 0, 0.2, 1]` | opacity only | chrome, secondary |
| `modalIn` | 0.5s | `[0.22, 1, 0.36, 1]` | y 8px→0, op 0→1 | overlays, popovers |
| `scaleSettle` | 0.5s | `[0.22, 1, 0.36, 1]` | scale 0.98→1, op 0→1 | rare focal emphasis |
| `sceneExit` | 0.45s | `[0.4, 0, 1, 1]` | opacity 1→0 | cross-scene |
| `stagger` | — | — | 0.08s between children | orchestrator |

Signature curve: `cubic-bezier(0.22, 1, 0.36, 1)` (ease-out-expo, "silky settle"). Used for all entrances.

### 6.2 Spring guidance

Spring is opt-in, not default. When used: `{ stiffness: 140, damping: 20, mass: 1 }`. Never used for multiple elements simultaneously.

### 6.3 Shipped snippets

- **React + Framer Motion**: a `variants` object exporting every token.
- **CSS-only fallback**: `@keyframes` + custom-property variables for projects without Framer.
- **Tailwind config fragment**: durations and easings as design tokens.

Each snippet is minimal and copy-pasteable, not a library.

## 7. `references/visual-system.md`

### 7.1 Palette

- Base: `#0a0a0b`
- Surface steps: `#121214`, `#1a1a1d`, `#232327`
- Text: `#f0f0f2` at alpha 1.0 / 0.6 / 0.35 for primary / secondary / tertiary
- Border: `rgba(255, 255, 255, 0.06)`
- Accent: restrained. Default is no accent color (monochrome dark plus whites). When one is needed, pick a single subdued hue — e.g. `#7aa2f7` (muted cool blue) or `#eef0f5` (cool near-white for highlight surfaces). Never mix two accent hues in one view.

### 7.2 Type

- Stack: `-apple-system, "SF Pro Text", Inter, ui-sans-serif, system-ui, sans-serif`.
- Scale (5 steps): display 56 / title 32 / heading 20 / body 15 / caption 13. Line-heights tuned per step (display tight around 1.05, body relaxed around 1.5); exact values set in the Tailwind config fragment.
- Weights: 400 / 500 / 600 only. Never 700+.

### 7.3 Spacing, radius, shadow

- Spacing: 4px grid — 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96 / 128.
- Radius: 8 / 12 / 16. Default 12.
- Shadow: one soft ambient (`0 1px 2px rgba(0,0,0,0.4), 0 8px 32px rgba(0,0,0,0.3)`). No stacked dramatic shadows.

### 7.4 Shipped snippets

- Tailwind `theme.extend` fragment covering colors, fontFamily, fontSize, spacing, borderRadius, boxShadow.
- CSS custom-properties fragment for non-Tailwind projects.

## 8. `references/reveal-patterns.md`

Five named sequencing patterns, each with a short React+Framer snippet that composes tokens from §6:

1. **scene-entry** — root fade-in then children stagger 80ms after.
2. **focal-first** — hero/title lands; supporting UI follows 200ms later.
3. **line-by-line** — split text into lines, stagger `fadeUp` at 80ms intervals.
4. **block-by-block** — whole sections stagger at 120ms intervals.
5. **progressive-disclosure** — secondary controls fade in only after primary content is interactive.

Each pattern includes a "when to use" note and a "do not combine with" note (e.g., never layer line-by-line on top of focal-first within the same element tree).

## 9. `references/audit-checklist.md` (Mode C)

Workflow:

1. **Score** the existing screen against 8 dimensions:
   - background and tone
   - type discipline
   - spacing and density
   - alignment
   - emphasis restraint
   - motion coherence
   - reveal sequencing
   - accessibility retained
   One-line `current → target` delta per dimension.
2. **Rank** the top-3 changes by visual-impact-per-edit.
3. **Red-flag sweep** — explicitly search for: glow spam, stacked gradients, bouncy springs, scale-pop on children, competing focal regions, empty minimalism (centered layout with no hierarchy).
4. **Apply** the ranked changes using tokens from §6–§8.
5. **Re-audit.**

Output format: `observation → change → diff`.

## 10. `references/examples/`

Three before/after transformations. Each file structure:

1. Before: code (or description) + audit findings.
2. Change list ordered by impact.
3. After: code.
4. "What we deliberately did not change" notes — reinforces restraint.

Required examples:

- **01-hero-section.md** — generic SaaS hero → keynote reveal. Demonstrates `sceneEnter`, focal-first, type scale rework, removed decorative gradient.
- **02-modal.md** — generic centered modal → anchored premium modal. Demonstrates `modalIn`, softened backdrop, accessibility preserved.
- **03-pricing-card.md** — busy 3-column pricing → calm comparison. Demonstrates border reduction, unified spacing, block-by-block on scroll.

Examples are the skill's truth test: if an agent cannot reproduce these from the tokens alone, the tokens are underspecified.

## 11. Cross-harness distribution

The canonical surface is `SKILL.md` + `references/`. Native consumers that understand Anthropic skill format read them directly.

**Native (no wrapper needed):**
- Claude Code
- Copilot CLI

**Wrappers in `integrations/`:**
- **`cursor/stagecraft.mdc`** — MDC rule with `alwaysApply: false`. Inlines a condensed SKILL.md plus inlined references because Cursor lacks progressive disclosure. Invoked via `@stagecraft`.
- **`codex/AGENTS.md`** — a paste-block users drop into their project AGENTS.md. Points at SKILL.md and lists trigger vocabulary.
- **`gemini/GEMINI.md`** — Gemini CLI equivalent.

**Build process:** `scripts/build-wrappers.sh` regenerates the three wrappers from canonical sources. Bash, no dependencies. Wrappers are never hand-edited; a CI check (deferred, not in MVP) can verify they are in sync.

**README install matrix:** per-harness install instructions, 4–5 lines each, plus a demo GIF.

## 12. Success criteria

The skill ships correctly when:

1. A fresh Claude Code session with the skill installed, given the prompt "turn this plain hero into a keynote-style reveal" and the `01-hero-section.md` "before" code, produces output matching the "after" code in motion timing, palette, and sequencing.
2. The same test in Cursor (with the MDC wrapper installed) produces equivalently styled output.
3. An agent without the skill, given only the trigger phrase "premium keynote-style hero," produces inconsistent output — confirming the skill adds determinism.
4. `SKILL.md` is under 100 lines.
5. No principle appears verbatim in more than one file.
